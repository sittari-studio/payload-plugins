# @sittari/payload-strings

A Payload CMS plugin that generates one localized `strings` global for developer-defined UI strings. Each scope becomes a named tab in the admin panel and a nested property in the API response, e.g. `general.cancelButton`.

## Install

```bash
pnpm add @sittari/payload-strings
```

Payload localization must be configured in the consuming project.

## Basic usage

```ts
import { buildConfig } from 'payload';
import { stringsPlugin } from '@sittari/payload-strings';

export default buildConfig({
  localization: {
    defaultLocale: 'en',
    locales: ['en', 'fr'],
  },
  plugins: [
    stringsPlugin({
      scopes: {
        general: {
          labels: 'General',
          strings: {
            cancelButton: {
              defaultValue: 'Cancel',
              description: 'Shown next to destructive actions.',
            },
            saveButton: {},
          },
        },
        auth: {
          labels: {
            en: 'Authentication',
            fr: 'Authentification',
          },
          strings: {
            loginTitle: {},
          },
        },
      },
    }),
  ],
});
```

## Reading the strings

The global is exposed through Payload's normal global endpoints and Local API. Scope keys become nested properties:

```ts
const strings = await payload.findGlobal({ slug: 'strings', locale: 'fr' });

strings.general.cancelButton; // "Annuler" (once translated)
strings.auth.loginTitle;
```

Runtime translation behavior — including whether missing locale values fall back to the default locale — is controlled by Payload's `localization` configuration and per-request `fallbackLocale` options, exactly as for any other localized field.

## `getTranslations`

For application code, `getTranslations` resolves keys like `general.cancelButton` in one shot. It loads every configured locale once with `fallbackLocale: false`, then returns a synchronous translator:

```ts
import { getTranslations } from '@sittari/payload-strings';

const t = await getTranslations({ payload, locale: 'en' });

t('general.cancelButton'); // stored value or defaultValue or null
t('general.cancelButton', 'fr'); // per-call explicit locale
```

Resolution order per key and locale:

1. The stored database value for that locale when it is a non-empty string.
2. Otherwise the configured `defaultValue`.
3. Otherwise `null`.

Because lookups happen with `fallbackLocale: false`, locales stay fully isolated: an untranslated string falls back to its developer-defined `defaultValue` instead of leaking another locale's wording.

The helper discovers both custom slugs (`slug`) and configured defaults automatically from internal metadata the plugin attaches to the Payload config, so it works without duplicating any configuration. It throws if `stringsPlugin` is not part of the Payload config.

## Configuration

The generated global is labeled `Translations` in English, Russian, and Ukrainian.

| Option      | Type                              | Default        | Description                                                         |
| ----------- | --------------------------------- | -------------- | ------------------------------------------------------------------- |
| `enabled`   | `boolean`                         | `true`         | Set to `false` to return the incoming Payload config unchanged.     |
| `slug`      | `string`                          | `"strings"`    | Slug of the generated global.                                       |
| `scopes`    | `StringsScopes`                   | Required       | Scope definitions keyed by the generated tab and API property name. |
| `overrides` | `(defaultGlobal) => GlobalConfig` | Default global | Extends or replaces the final global configuration. Applied last.   |

`scopes` is required unless the plugin is disabled, and every scope must define at least one string. Scope and string names are validated by Payload like any other field name.

### Strings

Each entry under a scope's `strings` becomes a localized text field. Labels are generated by Payload from the string key.

| Option         | Type                               | Description                                                                |
| -------------- | ---------------------------------- | -------------------------------------------------------------------------- |
| `defaultValue` | `string`                           | Shown as the admin placeholder while the string is empty, in every locale. |
| `description`  | `string \| Record<string, string>` | Admin description below the field, localized when keyed by locale code.    |

`defaultValue` is an editing hint only. It does not pre-seed or synchronize database values — strings stay empty until an editor saves them. When you read the global directly through Payload's Local or REST API, empty fields stay empty and `defaultValue` is not applied.

Through `getTranslations`, `defaultValue` becomes a runtime fallback: it is returned whenever the stored value for the requested locale is missing or an empty string, so developer-defined defaults never leave placeholder duty in direct Payload reads but still protect production UI through `t`.

### Custom slug

```ts
stringsPlugin({
  scopes: { general: { labels: 'General', strings: { ok: {} } } },
  slug: 'ui-strings',
});
```

### Compose with hooks

Use `overrides` to append hooks without losing the generated fields:

```ts
stringsPlugin({
  scopes: { general: { labels: 'General', strings: { ok: {} } } },
  overrides: (defaultGlobal) => ({
    ...defaultGlobal,
    hooks: {
      ...defaultGlobal.hooks,
      afterChange: [
        async ({ doc }) => {
          // Revalidate cached UI strings, trigger ISR, etc.
        },
      ],
    },
  }),
});
```

The callback must return a complete Payload `GlobalConfig`. Spread `defaultGlobal` (and nested properties you want to preserve) when making partial changes.

### Customize access

The generated global uses Payload's authenticated read/update defaults. Replace them through `overrides`:

```ts
import { adminAccess } from './access';

stringsPlugin({
  scopes: { general: { labels: 'General', strings: { ok: {} } } },
  overrides: (defaultGlobal) => ({
    ...defaultGlobal,
    access: {
      read: () => true,
      update: adminAccess,
    },
  }),
});
```
